# DESIGN.md — 집핀 디자인 SSOT 진입점

> **이 문서가 집핀(Jippin)의 디자인 시스템 정본(Single Source of Truth)의 진입점이다.**
> UI·문구·리포트·법적 고지 관련 작업을 시작하기 전에 반드시 이 문서와 그 하위 문서들을 먼저 읽는다. 임의로 색·폰트·문체·법적 고지 문구를 바꾸지 않는다.

- 상위 가이드: [`AGENTS.md §1`](../../AGENTS.md) 우선순위 1번 다음 단계로 본 문서를 읽는다.
- 정본 4종: [`BRAND.md`](BRAND.md) · [`COLOR_SYSTEM.md`](COLOR_SYSTEM.md) · [`TYPOGRAPHY.md`](TYPOGRAPHY.md) · 본 문서(원칙·인덱스)
- 현재 적용 위치: [`apps/web/tailwind.config.ts`](../../apps/web/tailwind.config.ts) · [`apps/web/app/layout.tsx`](../../apps/web/app/layout.tsx)

## 1. 우리는 누구를 위해 디자인하는가

집핀의 사용자는 **공동주택에 살고 있고, 비내력벽 철거(발코니 확장 등) 행위허가를 처음 마주하는 비전문가**다. 이 사람은:

- 평면도·구조도를 처음 본다. 도면 용어를 모른다.
- 행정 절차(관할 기관·신청 양식·필요 서류)에 익숙하지 않다.
- 인테리어 업체 견적이 합리적인지 판단할 기준이 없다.
- "지금 이게 가능한 거냐 아니냐"만 빠르게 알고 싶어 하면서도, 잘못 결정해 공사가 중단·원상복구되는 상황을 두려워한다.

이 사용자에 대한 우리의 응답은 **"차분한 전문가가 생활어로 사전검토를 설명해주는 경험"** 이다. 그 외 모든 시각/언어 선택은 이 응답을 강화하거나 약화시킨다.

## 2. 디자인 원칙 (Design Principles)

본 원칙은 모든 디자인·문구·컬러·폰트 결정의 상위 기준이다. 하위 문서(BRAND/COLOR_SYSTEM/TYPOGRAPHY)는 본 원칙에서 파생된 규칙이다.

### 2.1 근거가 보이게(Show your work)

- 판정에는 **근거(법령·고시 조항·도면 위치)** 가 함께 보인다.
- 결과 화면은 "가능/불가/보류"의 결론과 그 근거를 같은 시야에 배치한다.
- 근거가 부족할 때는 결론을 만들지 않고 "추가 확인 필요"로 멈춘다. 확신을 위조하지 않는다.

### 2.2 생활어 우선(Plain-Korean first)

- 전문 용어를 그대로 쓰지 않는다. 첫 등장 시 생활어로 설명하고, 정식 명칭은 괄호/툴팁으로 부기한다.
- 예: "비내력벽(건물 무게를 직접 받지 않는 벽)" / "행위허가(공동주택에서 구조 변경 시 받아야 하는 허가)".
- 자세한 문체 규칙은 [`TYPOGRAPHY.md §4 문체 가이드`](TYPOGRAPHY.md) 참조.

### 2.3 과장 금지·확정 금지(No false certainty)

- 집핀은 **사전검토**이지 행위허가 자체가 아니다. "확정", "보장", "100%", "통과" 같은 표현을 단독으로 쓰지 않는다.
- 모든 결과 화면·다운로드 산출물에는 [`AGENTS.md §4.6`](../../AGENTS.md) 의 법적 고지 문구가 반드시 포함된다.
- 색·강조·아이콘 어느 것도 법적 효력을 시사해서는 안 된다.

### 2.4 색은 의미를 강화하되 단독 전달은 금지(Color reinforces, never alone)

- 브랜드 색과 상태 색을 분리한다. 상세는 [`COLOR_SYSTEM.md`](COLOR_SYSTEM.md).
- 가능/불가/보류 상태는 **색 + 라벨 + 아이콘** 세 가지로 동시에 전달한다. (WCAG 색맹·저시력 사용자 대응)

### 2.5 모바일·짧은 세션 우선(Mobile-first, short-session-first)

- 사용자는 한 번의 채팅 세션에서 판정-근거-다음 행동을 모두 본다.
- 히어로 카피·과도한 마케팅 헤더는 쓰지 않는다. 화면의 1순위는 항상 "지금 사용자가 답을 받고 있는 질문"이다.

### 2.6 전문성은 보조 축으로(Professional accent, not primary face)

- 리포트·도면 분석·관리자 화면 같은 전문 영역에는 Blueprint Navy 보조 축을 쓴다. 메인 화면을 전문가용처럼 어둡고 무겁게 만들지 않는다.

## 4. 작업 가이드 — 에이전트·사람 공통

### 4.1 색을 바꾸려는가

1. [`COLOR_SYSTEM.md`](COLOR_SYSTEM.md) 의 토큰 표를 먼저 갱신한다.
2. `apps/web/tailwind.config.ts` 와 `apps/web/app/layout.tsx` 의 적용 위치를 동기화한다.
3. WCAG AA 4.5:1 (일반 텍스트) / 3:1 (UI 컴포넌트) 대비를 새 조합으로 다시 검증한다.
4. 의미가 바뀌는 변경(예: brand.cta 도입/폐기, status 색 매핑 변경)은 별도 ADR 또는 디자인 결정 기록을 남긴다.

### 4.2 문구를 바꾸려는가

1. [`TYPOGRAPHY.md §4 문체 가이드`](TYPOGRAPHY.md) 와 [`BRAND.md §4 톤앤매너`](BRAND.md) 를 동시에 확인한다.
2. 법적 고지 문구(`AGENTS.md §4.6`) 는 어떤 화면·문서에서도 단독으로 변경하지 않는다. 변경이 필요하면 CEO/Security Lead 가 함께 검토하는 별도 이슈를 연다.

### 4.3 폰트·타입스케일을 바꾸려는가

1. [`TYPOGRAPHY.md`](TYPOGRAPHY.md) 정본을 먼저 갱신한다.
2. 한국어 가독성(특히 리포트의 숫자·법령 조항·도면 좌표)에 회귀가 없는지 확인한다.

### 4.4 브랜드 자체를 재정의하려는가

- 본 문서와 `BRAND.md` 의 §1 브랜드 약속은 **CEO 봉인 영역**이다. 변경하려면 새 CEO 브리프 리비전이 필요하다.
- 색·폰트 등 표현 영역은 ADR 또는 디자인 결정 기록(`docs/design/decisions/` 신설 가능) 으로 변경한다.

### 4.5 레이아웃 컨테이너 폭 — 바깥은 항상 lg, 좁힘은 PageColumn

라우트별 sm/lg 분기(와 등록 누락 시 암묵 sm 낙하)는 폐지됐다(2026-07 UI 정비). 정본 규칙:

- **바깥 `Container` 는 전 페이지 `lg`(헤더와 동일)로 고정한다.** 페이지 전환 시 배경·헤더의 정렬 앵커가 움직이지 않는다. `SiteShell` 이 일괄 적용하므로 페이지에서 등록할 것이 없다.
- **좁아야 하는 콘텐츠는 컨테이너가 아니라 `PageColumn`(`apps/web/components/ui/PageColumn.tsx`)으로 좁힌다.**

| PageColumn width | 폭 | 용도 |
|---|---|---|
| `full` (기본) | 제한 없음 | 목록·상세·리포트·랜딩 |
| `prose` | 720px | 약관·개인정보처리방침 등 읽기 문서, 채팅 컬럼과 동급 |
| `form` | 560px | 로그인·가입·단일 입력 폼 |
| `funnel` | 460px | 원-퀘스천 퍼널(우리집 체크) |

- 페이지 타이틀+부제 블록은 `PageHeader` 컴포넌트를 쓴다(크기·간격 SSOT — 페이지별 fz 오버라이드 금지).

### 4.6 간격(spacing)·수직 리듬 — 정본

- **컴포넌트 내부 수직 리듬은 Mantine 토큰(xs 10 / sm 12 / md 16 / lg 20 / xl 32)만 쓴다.** 임의 숫자 px 간격은 4/8/12/16/24/32 배수 안에서만, 그리고 토큰으로 표현 불가능할 때만 허용.
- **기능 페이지 상단 여백**: `SiteShell` 의 `Container py="xl"` 하나로 통일(페이지에서 추가 상단 여백 금지).
- **랜딩 섹션 세로 패딩**: `var(--jippin-section-py)`(clamp 3~5rem) 공용 토큰만 사용. 페이지별 clamp 발명 금지.
- **카드 내부 패딩**: 테마 기본(`padding="lg"`)을 쓴다. md/xl 오버라이드는 명시적 사유가 있을 때만.
- **radius**: 컨트롤(md=8px) · 표면(lg=12px) · 칩/필(999) 3단계만. 개별 px radius 금지.

### 4.7 버튼·인터랙션 위계 — 정본

| 위계 | 사양 | 규칙 |
|---|---|---|
| 전환 CTA | `CtaButton`(coral filled, 어두운 라벨) | 상담·견적·다운로드 등 **전환에만**, 한 화면 1회 (`COLOR_SYSTEM.md §2.1`) |
| 1차 액션 | `Button color="jippin" variant="filled" size="md"` | 제품 기능 진입(사전검토 시작, 폼 제출 등) |
| 2차 액션 | `variant="light"` 또는 `outline` | 보조 진행(다시 검색, 취소 아닌 대안) |
| 3차 | `variant="subtle"` | 최소 강조. 파괴적 액션만 `color="danger"` |

- 버튼 크기는 페이지 CTA=md(42px)·인라인=sm(36px) 2단만.
- **터치 타깃 최소 44×44px** — 아이콘 버튼·칩·모바일 인터랙션 요소 전부. 아이콘이 작아도 히트 영역은 44px 를 보장한다.
- 코랄을 상태·배지·금액·마커에 쓰지 않는다(상태는 `status.*`). 본문 링크는 밑줄 기본(`Anchor underline="always"` 테마 기본값).
- 내부 내비게이션은 `component={Link}`(next/link). `component="a"` 는 외부 링크 전용.
- **베타 표시**: 정식 출시 전 기능은 내비 라벨 뒤 첨자 텍스트 `BETA`(10px/600, uppercase, 링크 색 상속)로 표시한다(`SiteShell` 의 `NavItem.badge`). 필 배지·색 면·코랄을 쓰지 않는다 — 베타는 기대치 고지이지 홍보가 아니다(운영자 선택, 2026-09).

### 4.8 반응형·모바일 — 정본

- 브레이크포인트는 Mantine 기본(sm=48em, md=62em, lg=75em)을 쓴다. 커스텀 미디어쿼리도 같은 경계만.
- **모바일은 축소가 아니라 재배치다**: 3열 이상 그리드는 base 1열, 표는 자체 가로 스크롤 컨테이너 또는 카드 분할.
- **safe-area**: 하단 고정 요소(채팅·퍼널 도크 등)는 `env(safe-area-inset-bottom)` 여백 필수. `viewport.viewportFit='cover'` + `interactiveWidget='resizes-content'` 는 root layout 에서 설정돼 있다.
- **가상 키보드**: 채팅 등 100dvh 레이아웃은 `resizes-content` 전제로 설계한다. 터치 기기에서 Enter 는 줄바꿈(전송은 버튼)이다.
- **모바일 내비게이션**: 우상단 햄버거 + 우측 `Drawer` 단일 패턴이다(하단 탭바는 도입하지 않는다 — 햄버거와 중복). 햄버거 히트 영역은 44px.
- 법적 고지·사업자 표기는 모바일에서도 페이지 하단에 상시 노출한다(compact 허용, Drawer 단독 노출 금지).

### 4.9 그래픽 모티프 — 제도(製圖) 시스템

집핀의 시각 정체성은 "도면을 다루는 서비스"를 배경 신호로 상시 전달한다. 과장 금지 원칙(§2.3)에 따라 모티프는 항상 **약하게**.

- **격자 캔버스**: 페이지 배경은 `brand.canvas`(#FFFFFF) 위 2중 제도 격자 — 마이너 32px(`--jippin-grid-minor`), 메이저 160px(`--jippin-grid-major`), 라인은 Blueprint Navy 알파. 카드·헤더·푸터 등 표면은 불투명으로 유지해 격자는 여백에서만 드러난다. (`globals.css body::before`)
- **가독성 마스크(필수)**: 카드 없는 맨 텍스트에 격자선이 겹치면 취소선처럼 읽힌다. 격자 레이어에는 가로 마스크를 걸어 **콘텐츠 컬럼(중앙)에서는 격자를 완전히 지우고 좌우 거터에서만 보이게** 한다. 좁은 화면(모바일)은 전체가 콘텐츠 영역이라 격자가 자연히 사라진다 — 읽기 우선. 텍스트 블록에 개별 배경을 칠어 격자를 가리는 방식은 쓰지 않는다(표면 남발 방지).
- **패럴랙스(0.22× 단일 속도)**: 격자는 콘텐츠의 0.22× 속도로 스크롤을 따라온다(`GridParallax` → `--jippin-grid-scroll`). 완전 고정은 콘텐츠와 유리되어 어색하고 1:1 은 밋밋하다는 결정(2026-07). **마이너/메이저 격자는 반드시 같은 속도** — 속도를 달리하면 두 격자가 서로 미끄러져 어긋나 보인다. `prefers-reduced-motion` 은 고정 유지.
- **치수선 구분자**: 섹션 구분에 `.jp-dimline`(양끝 틱이 있는 네이비 라인).
- **도면 일러스트**: 빈 상태·에러·404 는 제너릭 아이콘 대신 평면도 라인 일러스트(브랜드 토큰 색, 인라인 SVG).
- **Blueprint Navy 의 자리**: 리포트·도면 분석의 전문 축(§2.6). 마케팅 히어로·채팅 본문에 남용하지 않는다.
- 하단 고정 도크의 배경은 격자를 갑자기 지우는 단색 띠가 되지 않도록 반투명+blur 를 쓴다.
