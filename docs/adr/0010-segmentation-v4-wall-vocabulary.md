# ADR 0010 — 도면 세그멘테이션 v4: 벽 어휘 3분화와 원본 해상도 타일 추론

- **상태**: **Accepted (2026-08-13)** — 모델 레포 v4 인계에 따른 앱 정합.
- **관련**: ADR-0001 §7.4(AI 모델 선정), `packages/contracts/schemas/segmentation-result.schema.json`
  (**1.3.0 → 1.4.0**), `apps/api/src/agent/tools/segmentation.py`,
  `apps/web/components/a2ui/cards/FloorplanOverlayCard.tsx`.
- **대체 아님**: 3단계 분석 파이프라인(세그멘테이션 → VLM → 정합성 머지)과 HITL 전제는 유지된다.

## 배경 / 문제

기존 학습 데이터의 벽 속성 라벨에 오류가 있어 도면 573장을 전문가가 재작업했고, 그 과정에서
두 가지가 드러났다.

**(1) 벽 어휘의 의미가 앱에서 뒤집혀 있었다.** 라벨 매니저의 벽 속성은 3종(철근콘크리트벽 /
기타벽 / 비내력벽)인데, **비내력벽이 변환 파이프라인 매핑에 없어 `wall_unknown` 으로 조용히
폴백**되고 있었다(573장에서 27,407개 = 벽의 45%). 그 결과 v3 까지의 앱은 판단을 보류한
'기타벽'(`wall_other`)을 초록 **비내력벽 후보**로 그려 철거 가능성 판단에 태우고, 실제
비내력벽은 회색 '구조 불확실'로 밀어내고 있었다.

**(2) 입력 해상도가 벽 인식의 결정적 병목이었다.** 도면 원본 중앙값은 4963×3509 인데 모델은
1536×1536 으로 축소해 학습했다. 선 폭이 3.2배 줄어 빗금 해치가 소실되고, 마스크 헤드가
stride 4 에서 동작하는 것까지 겹쳐 얇은 벽이 서브픽셀이 됐다 — "벽이 어디 있는지는 알지만
개별 벽을 가르지 못하는" 상태(벽 IoU 0.2~0.3 vs 인스턴스 AP 0.02~0.06).

## 결정

| 항목 | 결정 |
|---|---|
| 클래스 수 | **19** (STR 6 + SPA 13). `wall_nonbearing` 신설. |
| 벽 어휘 의미 | `wall_reinforced_concrete`=내력(RC) 후보 / `wall_nonbearing`=작업자가 **확정한** 비내력 / `wall_other`=도면만으로 판단을 **보류한 미확정** 벽. `wall_unknown` 은 v3 이하 과거 데이터 호환용으로만 존치(v4 산출 없음). |
| 판단 스키마 매핑 | `wall_nonbearing → NON_LOAD_BEARING`, `wall_other`·`wall_unknown → UNKNOWN`(룰엔진 HOLD), `wall_reinforced_concrete → LOAD_BEARING`. **비내력 후보군 = nonbearing ∪ other 지만 신뢰 등급을 나누는 것이 분리의 목적**이다. |
| 입력 해상도 | **원본 픽셀 그대로 전송.** 리사이즈 파라미터(`max_inference_side`)를 계약·설정·요청에서 제거한다. 핸들러가 1536 타일/256 겹침으로 잘라 추론 후 전체 좌표로 합친다. |
| threshold | 운영 기본 **0.35**(구 0.5). 비내력 계열은 점수가 낮게 나와 0.5 에서 상당수가 걸러진다(모델 평가도 0.35 축). |
| 작업량 상한 | `max_tiles`(기본 80)를 **명시 전송**한다. 업로드 게이트는 content-type 과 인코딩 크기(50MiB)만 보므로, 고압축 이미지가 디코드 후 거대한 캔버스로 펼쳐지면 타일 루프가 폭주한다. |
| 조각 병합 | 타일 경계에서 갈라진 조각을 앱에서 잇는다. **양쪽 모두 경계 조각**이고 원본 도형 사이 거리가 3px 이내이며 두 타일 집합이 **겹치지 않는** 쌍만 대상(한 타일을 공유하면 경계로 갈린 조각이 아니라 남남 벽). VLM 교정으로 클래스가 같아지면 한 번 더 병합한다. |
| 저장분 호환 | 오버레이 payload 에 `vocab_version` 을 싣는다. 판별자가 없는 payload(=v3 저장분)는 옛 의미로 정규화해 그린다. |
| 배포 스큐 | web(Vercel)·api(Fly)는 따로 배포되고 열려 있던 탭은 옛 번들로 남는다. 오버레이 payload 는 미확정 벽을 **옛·새 카드가 모두 회색으로 읽는 `wall_unknown`** 으로 통일해 내보낸다 — 옛 카드가 미확정 벽을 초록 '철거 가능 후보'로 그리는 반전을 막는다. 판단객체·룰 입력은 원본 v4 어휘 그대로. |

### 근거 — 해상도 레버 (동일 GT·동일 프로토콜)

| class | v4 IoU | v3 IoU | v4 AP | v3 AP |
|---|---|---|---|---|
| `wall_nonbearing` | 0.547 | 0.245 | 0.301 | 0.061 |
| `wall_other` | 0.430 | 0.183 | 0.177 | 0.019 |
| `wall_reinforced_concrete` | 0.819 | 0.590 | 0.597 | 0.300 |
| `door` | 0.740 | 0.423 | 0.575 | 0.372 |
| `window` | 0.824 | 0.621 | 0.670 | 0.452 |

입력을 축소하면 성능이 붕괴한다: 원본 픽셀 타일 structure mean IoU **0.672** vs 1536 축소
**0.0007**. 이 값이 "리사이즈 금지"를 계약 수준으로 못 박는 근거다.

## 결과 / 트레이드오프

- **판정 분포가 이동한다.** `wall_other` 가 `UNKNOWN` 이 되면서 그 벽만 고른 세션은 룰엔진
  HOLD(추가 확인 필요)로 떨어진다. 도면만으로 판단을 보류한 벽에 철거 가능성 판단이 붙던 것을
  막는 의도된 변화다.
- **공간 13클래스가 후퇴했다**: `space_mean_iou` 0.761 → 0.688 (−7.3pt). 모델 레포에서 SPA 도
  원본 해상도로 학습해 개선 예정.
- **지연이 커진다.** 도면당 타일 수만큼 forward 가 돌아(4963×3509 ≈ 12회) CPU 인스턴스에서
  도면당 수 분이다. 예산은 콜드스타트 폴링 300s(기존 창 유지) + 추론 600s + VLM·왕복 여유를
  합쳐 런 wall-clock 1200s 로 잡았다. **근본 해법은 비동기 처리(작업 큐 + 완료 알림) 또는
  GPU 전환**이며 후자는 비용 결정이라 별도 승인 대상이다.
- **벽 인스턴스 AP 절대값은 여전히 낮다**(`wall_other` 0.177, `wall_nonbearing` 0.301).
  개별 벽 분리는 개선됐지만 완전하지 않아 **HITL 전제는 유지**된다.
- 라벨 근거는 573장이라 전체 도면 분포를 대표하지 않을 수 있다. 특히 `wall_nonbearing` 은 이
  573장에서만 학습돼 데이터 기반이 얇다 — 전문가 라벨 추가 확보가 다음 성능 레버다.
